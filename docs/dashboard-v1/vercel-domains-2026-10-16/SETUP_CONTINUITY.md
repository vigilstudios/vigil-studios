# Purchased-domain setup continuity

The customer selects **I’ve bought it — continue setup** after completing checkout in their own Vercel account. Vigil validates the current saved choice and creates or resumes the existing pending domain. The next screen is **Open Domains**, with the domain already selected in the guide. It does not repeat domain entry, provider selection or a sign-in acknowledgement. The same tenant/website-bound intent determines this navigation when returning from Overview or onboarding.

Each screen still contains one task. Navigation to Domains, selecting the named domain and finding DNS Records remain separate tasks. Type, Name, Value, default TTL and saving one record are combined. A second record is a separate screen. Vercel’s inline form does not require an extra “open Add record” acknowledgement. Individual Copy buttons provide feedback; Add/Save happens in Vercel, followed by **I saved this record** and **Check my setup** in Vigil.

The official [DNS documentation](https://vercel.com/docs/domains/managing-dns-records) was fetched with Context7 and inspected in the browser on October 17, 2026. Its [team Domains picker](https://vercel.com/d?to=%2F%5Bteam%5D%2F%7E%2Fdomains&title=Go+to+Domains) avoids guessing the customer’s account/team. Simplified native illustrations identify the sidebar, domain row and DNS Records section; they are explicitly illustrations rather than screenshots. The form instructions use Vercel’s documented Add action and allow Save for edits. Staff preview uses explanatory placeholders, never a real proof token or an enabled checker.

Submitting the purchased-domain continuation does not confirm payment or authorize customer DNS access. Staff impersonation and member roles cannot use that continuation. A cancelled/replaced/version-stale choice is rejected before starting setup. Generic existing-owned-domain setup keeps its provider/sign-in path. Prelaunch output remains ownership-only, real checks control readiness/connection, and existing launch gates remain intact.

No migration, Production environment change, registrar transaction, beta API, customer DNS write or Scar publication is part of this release. Automatic cross-account DNS remains disabled under the existing feasibility gate. Validation and release receipts are under `evidence/setup-continuity/`; the shared dashboard is released only after current checks and isolated Preview browser QA pass. Rollback is a shared-code revert; customer domain rows remain compatible with the existing owned-domain guide.
