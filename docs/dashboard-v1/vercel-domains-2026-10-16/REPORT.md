# Vercel domain journey — partial implementation

Search and durable external handoff are implemented. Automatic cross-account connection is unproven and disabled. [Feasibility receipt](FEASIBILITY.md) and provider inquiry identify the missing dependency. This is not the completed end-to-end objective.

One website-bound intent records the normalized selected name, server-rechecked advisory quote/time, external handoff time, version and phase. Continue saves before opening a fixed Vercel search URL. Refresh, return navigation and another signed-in device recover Connect plus Return to Vercel and Choose another domain. The fallback link is always present even if a popup is blocked. There is no callback or Purchased state. Replacing/cancelling an intent cannot mutate an existing domain or website. A cancelled intent remains versioned to reject stale requests.

Domain and onboarding share the journey. Existing own/need/unsure/later brief/autosave remains separate; Vercel is an additive registrar identifier. Overview resumes the saved name. Existing-owned-domain guides remain available independently of Vercel discovery. Search accepts exact registrable ICANN names/IDN, rejects URL/port/subdomain input, fails safely on malformed/timeout/outage responses and retains no provider tokens. Unknown/unavailable results carry no invented prices.

The rollout switch is server-only `DOMAIN_HANDOFF_ENABLED=true`; default false. Customer DNS automation has no enable switch and cannot be enabled by that flag. All mutation actions require actual customer owner/manager membership; staff impersonation cannot stand in for customer consent. Read RLS is tenant-bound. Writes are a service-only, serialized, version-checked RPC that rechecks customer membership and website ownership. No credentials are stored in the intent; no provider IDs are introduced. The existing provider registry's DNS/deployment capabilities are unchanged; public discovery is its own credential-free adapter, not a registrar purchase provider.

Migration 0047 is additive and compatible with the previous application. Deploy compatible code with the switch off, review/apply migration, verify types and RLS, then enable only search/handoff in the validated environment. Rollback: disable the switch and redeploy previous shared application; leave the additive intent table in place to preserve saved choices. Do not drop production data as rollback. No customer-site publication, DNS cutover, contact/booking activation or review mutation is part of this release.

Validation/release receipts are recorded below as they complete. Logs in evidence are fresh for this checkout; failed initial attempts are not acceptance results. The current repository schema includes both public and vigil in its single generated `types/database.types.ts` file.
